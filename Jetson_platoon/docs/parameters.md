# 파라미터 정리

플래툰 프로젝트에서 **실측값으로 교체하거나 실차 시험으로 튜닝해야 하는 값**들입니다.
현재 코드에 들어있는 값은 전부 알고리즘 구조 검증용 임시값이며, 그대로 실차에 올리면 안 됩니다.

우선순위 표기:
- **[필수]** — 실측하지 않으면 알고리즘이 물리적으로 틀린 값을 냄
- **[튜닝]** — 돌려보면서 조정. 초기값으로 일단 굴러는 감
- **[확정]** — 팀에서 규칙을 정해야 하는 값 (측정 대상이 아님)

---

## 1. 차량 제원 — 실측 필요

**파일: `driving_control.py`** (파일 상단 "차량 제원" 블록)

| 파라미터 | 현재값 | 의미 | 우선순위 |
|---|---:|---|---|
| `WHEELBASE_M` | 0.20 | 앞바퀴 축 ~ 뒷바퀴 축 거리 (m) | **[필수]** |
| `MAX_STEERING_RAD` | 30° | 서보가 낼 수 있는 최대 조향각 | **[필수]** |

`WHEELBASE_M`은 pure pursuit 공식 `δ = atan2(2·L·sin(α), Ld)`에 직접 들어가므로,
틀리면 팔로워 조향각 전체가 비례해서 틀어집니다. **줄자로 재서 넣으세요.**

`MAX_STEERING_RAD`는 서보 최대각을 넘는 명령이 나가지 않게 잘라주는 안전장치입니다.
STM32 쪽 서보 설정과 반드시 같은 값이어야 합니다.

## 2. 속도 범위 — 실측 필요

**파일: `platoon_fsm.py`** ("제어 이득" 블록 아래)

| 파라미터 | 현재값 | 의미 | 우선순위 |
|---|---:|---|---|
| `V_MIN` | 0.0 | 목표속도 하한 (m/s) | **[필수]** |
| `V_MAX` | 1.0 | 목표속도 상한 (m/s) | **[필수]** |

**파일: `platoon_fsm.py`** ("적합도 계산 파라미터" 블록)

| 파라미터 | 현재값 | 의미 | 우선순위 |
|---|---:|---|---|
| `MAX_SPEED_DIFF` | 1.0 | 속도 유사도 점수 정규화 기준 Δv_max (m/s) | **[필수]** |

`MAX_SPEED_DIFF`는 보통 `V_MAX`와 같거나 조금 작게 잡습니다.
이 값이 실제 차량 속도 범위보다 크면 속도 차이가 나도 점수가 잘 안 깎여서
적합도 판단이 무뎌집니다.

> **측정 방법**: STM32에 일정 PWM을 주고 일정 거리를 주행시켜 시간을 재면 됩니다.
> 최저속은 "모터가 끊기지 않고 도는 최소 속도"를 찾으세요.

## 3. 거리 관련 — 실측 필요

**파일: `platoon_fsm.py`** ("적합도 계산 파라미터" 블록)

| 파라미터 | 현재값 | 의미 | 우선순위 |
|---|---:|---|---|
| `D_SAFE_M` | 0.5 | 안전거리. 이보다 가까우면 거리점수 0 | **[필수]** |
| `MAX_JOIN_DISTANCE_M` | 5.0 | 최대 후보 거리 (= 적합도 d_max) | **[튜닝]** |

**파일: `platoon_fsm.py`** ("JOIN / MAINTAIN / EXIT 파라미터" 블록)

| 파라미터 | 현재값 | 의미 | 우선순위 |
|---|---:|---|---|
| `TARGET_DISTANCE_M` | 0.8 | 목표 차간거리 (설계문서 초기값) | **[튜닝]** |
| `DISTANCE_TOLERANCE_M` | 0.1 | 결합 완료 판정 거리 오차 | **[튜닝]** |
| `D_RELEASE_M` | 2.0 | 플래툰 해제 완료 거리 | **[튜닝]** |

`D_SAFE_M`은 차량 길이와 제동거리를 고려해서 정해야 합니다.
**`TARGET_DISTANCE_M`보다 반드시 작아야 하고**, 아니면 목표거리에 도달해도
거리점수가 0이 되는 모순이 생깁니다. (현재: 0.5 < 0.8 ✓)

`MAX_JOIN_DISTANCE_M`은 **UWB 실제 측정 가능 거리를 넘으면 안 됩니다.**
ESP32 팀원에게 UWB 모듈의 신뢰 가능한 최대 측정거리를 확인하세요.

## 4. 통신 품질 — 실측 필요

**파일: `platoon_fsm.py`** ("적합도 계산 파라미터" 블록)

| 파라미터 | 현재값 | 의미 | 우선순위 |
|---|---:|---|---|
| `RSSI_MIN` | -90.0 | RSSI 정규화 하한 (점수 0) | **[필수]** |
| `RSSI_MAX` | -30.0 | RSSI 정규화 상한 (점수 1) | **[필수]** |
| `PDR_WEIGHT` | 0.7 | 통신품질 = PDR×α + RSSI×(1-α) | [튜닝] |

> **측정 방법**: 차량 두 대를 여러 거리(0.5m, 1m, 3m, 5m)에 놓고 ESP-NOW RSSI를
> 로깅하세요. 실제로 관측된 최소/최대값을 넣으면 됩니다.
> 범위가 실제와 다르면 통신품질 점수가 항상 0이거나 항상 1이 되어 무의미해집니다.

## 5. 제어 이득 — 실차 튜닝

**파일: `driving_control.py`** ("차선추종 PID 게인" 블록)

| 파라미터 | 현재값 | 의미 | 튜닝 순서 |
|---|---:|---|---|
| `LANE_KP` | 0.5 | 차선 오프셋 → 조향각 비례게인 | 1순위 |
| `LANE_KI` | 0.0 | 적분게인 | 3순위 |
| `LANE_KD` | 0.0 | 미분게인 | 2순위 |
| `LANE_I_LIMIT` | 0.5 | 적분 와인드업 제한 | [튜닝] |
| `LANE_LOST_TIMEOUT_S` | 0.3 | 라인 유실 후 정지까지 시간 (초) | [튜닝] |

**튜닝 순서**
1. `KP`만 놓고 시작 (`KI=KD=0`). 직선에서 안 흔들리고 코너를 도는 최대값을 찾음
2. 코너 반응이 굼뜨면 `KD`를 0.005부터 조금씩 올림
   — **D항은 1/dt(50Hz면 50배)로 증폭되므로 KP보다 훨씬 작게 잡아야 함**
3. 직선에서 한쪽으로 계속 치우치면 `KI`를 아주 조금 추가

`LANE_LOST_TIMEOUT_S`는 짧으면 그늘·반사에 자꾸 멈추고, 길면 라인 이탈 후에도
계속 달립니다. 0.3초로 시작해서 조정하세요.

---

**파일: `platoon_fsm.py`** ("제어 이득" 블록)

| 파라미터 | 현재값 | 의미 | 단계 |
|---|---:|---|---|
| `K_D` | 0.4 | 차간거리 오차 → 속도 보정 | MAINTAIN |
| `K_V` | 0.6 | 리더-팔로워 속도차 보정 | MAINTAIN |
| `K_F_JOIN` | 0.5 | JOIN 시 팔로워 가속 이득 | JOIN |
| `K_L_JOIN` | 0.3 | JOIN 시 리더 감속 이득 | JOIN |
| `K_EF_EXIT` | 0.3 | EXIT 시 팔로워 감속 이득 | EXIT |
| `K_EL_EXIT` | 0.3 | EXIT 시 리더 가속 이득 | EXIT |

전부 **[튜닝]** 대상입니다. 설계 문서에도 "실제 적용 전 결정해야 한다"고만 되어 있고
구체값이 없습니다.

**튜닝 순서 권장**: `K_D` → `K_V` → JOIN 이득 → EXIT 이득
거리 유지가 먼저 안정돼야 나머지가 의미 있습니다.

> `K_D`가 너무 크면 차간거리가 진동합니다(붙었다 멀어졌다 반복).
> `K_V`는 리더의 속도 변화를 미리 따라가게 해주므로, 리더가 가감속할 때
> 팔로워가 늦게 반응하면 이 값을 올리세요.

> 목표속도 계산은 `platoon_fsm.py` 한 곳에서만 합니다.
> (`driving_control.py`는 조향각만 계산) 이득을 고칠 때 한 파일만 보면 됩니다.

## 6. 안전 제한값

**파일: `platoon_fsm.py`** ("JOIN / MAINTAIN / EXIT 파라미터" 블록)

| 파라미터 | 현재값 | 의미 | 출처 |
|---|---:|---|---|
| `MAX_CLOSING_SPEED` | 0.3 | 최대 접근속도 (m/s) | 설계문서 §19.5 |
| `MAX_SPEED_STEP` | 0.05 | 한 주기 속도 변화량 제한 (m/s) | 설계문서 §19.5 |
| `APPROACH_ZONE_M` | 0.3 | 목표거리 근접구간 | 설계문서 §19.5 |
| `SPEED_TOLERANCE` | 0.1 | 결합완료 판정 속도차 | 설계문서 §19.7 |
| `STABLE_TIME_S` | 1.0 | 안정 유지시간 (초) | 설계문서 §19.7 |
| `PARTNER_LOST_TIMEOUT_S` | 1.0 | 상대 차량 정보 두절 판정 시간 (초) | 설계문서 §15.3 |
| `OBSTACLE_STOP_DISTANCE_M` | 0.30 | 초음파 즉시정지 거리 (m) | **[필수]** 제동거리 실측 후 |
| `OBSTACLE_SLOW_DISTANCE_M` | 0.60 | 초음파 감속 시작 거리 (m) | [튜닝] |
| `CUTIN_MARGIN_M` | 0.15 | 끼어듦 판정 여유. UWB/초음파 측정오차보다 커야 오탐 방지 | **[필수]** |
| `OBSTACLE_SLOW_FACTOR` | 0.5 | 감속 시 목표속도 배율 | [튜닝] |
| `JOIN_RESPONSE_TIMEOUT_S` | 2.0 | 결합 요청 응답 대기 한계 (초) | 문서 명시 없음 |
| `SETUP_TIMEOUT_S` | 2.0 | PLATOON_SETUP 대기 한계 (초) | 문서 명시 없음 |

설계문서에 초기값이 명시된 값들이라 **그대로 시작하면 됩니다.**
다만 문서에도 "실차시험으로 확정한다"고 되어 있으니, 결합 동작이 거칠면
`MAX_CLOSING_SPEED`와 `MAX_SPEED_STEP`을 낮추세요.

## 7. 팀에서 규칙을 정해야 하는 값

측정이 아니라 **결정**이 필요한 항목들입니다.

| 파라미터 | 파일 | 정해야 할 것 |
|---|---|---|
| `CHECKPOINT_ADJACENT_RANGE` | `platoon_fsm.py` | 체크포인트 "인접" 판정 기준. 체크포인트 체계 확정 후 |
| `lane_ok` (현재 항상 True) | `platoon_fsm.py` `_prefilter()` 내부 | 차선 인접 규칙. 트랙 차선 구조 확정 후 |
| `LANE_ALIGN_OFFSET_TOLERANCE` | `platoon_fsm.py` | 0.15 기준(정규화 오프셋). 카메라 차선 중앙 오프셋 허용치 |
| `vehicle_id` | `main.py` `main()` 내부 | 차량별 고유 ID 부여 방식 |
| 시리얼 포트 경로 | `main.py` `open_stm32_port()` | `/dev/ttyAMA0` vs `/dev/ttyUSB0` |
| `reason_code` 체계 | `v2x_protocol.py` `PlatoonJoinReject` | 거절 사유 코드 정의 |
| 조향 부호 방향 | `stm32_protocol.md` §5.2 | 좌회전=양수가 실제 서보와 맞는지 |
| Baudrate | `stm32_protocol.md` §2 | 115200 유지 여부 |
| 초음파 연결 위치 | `stm32_protocol.md` §5.3 | STM32 직결 vs RPi 직결 |

## 8. 측정 체크리스트

실차 시험 전에 아래를 순서대로 채우세요.

- [ ] 축간거리 실측 → `WHEELBASE_M`
- [ ] 서보 최대 조향각 확인 → `MAX_STEERING_RAD` (STM32 설정과 일치)
- [ ] 최저/최고 주행속도 측정 → `V_MIN`, `V_MAX`, `MAX_SPEED_DIFF`
- [ ] UWB 신뢰 측정거리 확인 → `MAX_JOIN_DISTANCE_M`
- [ ] 거리별 RSSI 로깅 → `RSSI_MIN`, `RSSI_MAX`
- [ ] 안전거리 결정 → `D_SAFE_M` (반드시 `TARGET_DISTANCE_M`보다 작게)
- [ ] 라인트레이싱 P게인 튜닝 → `LANE_KP`
- [ ] 2대 결합 시험하며 → `K_D`, `K_V`
- [ ] 차선 정렬 허용 오프셋 → `LANE_ALIGN_OFFSET_TOLERANCE`
- [ ] 제동거리 측정 → `OBSTACLE_STOP_DISTANCE_M` (실제 제동거리보다 여유 있게)
- [ ] UWB·초음파 동시 측정 오차 확인 → `CUTIN_MARGIN_M` (오차보다 크게 잡아야 오탐 없음)
- [ ] V2X 실제 수신 주기 확인 후 → `PARTNER_LOST_TIMEOUT_S` (수신 주기의 3~5배 권장)

## 9. 라인트레이싱 (lane_tracing.py) — 하드웨어 확정 전 전부 임시값

친구 코드에서 이식하면서 원본 그대로 둔 값들입니다. 실제 트랙 바닥재질/조명/카메라
높이가 정해지면 `lane_debug_server.py`로 화면 보면서 눈으로 튜닝하세요.

| 파라미터 | 현재값 | 의미 |
|---|---:|---|
| `CANNY_LOW`, `CANNY_HIGH` | 50, 150 | 에지 검출 임계값. 라인이 흐리게 잡히면 낮추고, 노이즈 많으면 올리기 |
| `ROI_TOP_RATIO` | 0.5 | 화면 위쪽 몇 %를 무시할지. 카메라 장착 각도에 따라 조정 |
| `HISTOGRAM_MIN_PEAK` | 100 | 이 값 이상이어야 "차선 있음"으로 판정. 너무 낮으면 노이즈를 차선으로 오인 |
| `WINDOW_MARGIN` | 30 | 슬라이딩 윈도우 폭(px). 커브가 급하면 넓혀야 놓치지 않음 |
| `MIN_FIT_POINTS` | 50 | 다항식 피팅에 필요한 최소 에지 픽셀 수 |
| `SOLID_LEN_RATIO`, `DASHED_LEN_RATIO` | 0.45, 0.10 | 실선/점선 판별 기준 (허프 변환 최대선분 길이 비율) |

**주의**: 이 값들은 다른 항목들과 달리 실측으로 정해지는 "하나의 정답"이 없고,
**카메라 해상도·높이·각도·바닥 재질이 바뀔 때마다 다시 잡아야** 합니다. 최종
하드웨어가 고정되기 전까지는 튜닝을 미뤄도 되는 항목입니다.
