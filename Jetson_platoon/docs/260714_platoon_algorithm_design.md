# V2X 기반 플래툰 알고리즘 설계 정리

## 1. 문서 목적

본 문서는 V2X 통신으로 수신한 주변 차량 정보와 자차의 주행 정보를 이용하여 플래툰 후보를 평가하고, 적합한 차량과 전용 통신을 설정한 뒤 실제 차량 결합 단계로 진입하는 알고리즘을 정리한다.

현재 설계 범위는 다음과 같다.

> 주변 차량 탐색 → 절대조건 검사 → 플래툰 적합도 계산 → 결합 요청 및 승인 → 플래툰 전용 통신 설정 → 차량 결합 → 플래툰 주행 진입

예외상황과 플래툰 유지·해제 알고리즘은 후속 단계에서 구체화한다. 현재는 V2X 데이터와 자차 주행 데이터가 모두 정상적으로 수신되는 상황을 가정한다.

---

## 2. 시스템 내 플래툰 알고리즘의 역할

플래툰 알고리즘은 모터나 조향장치를 직접 제어하지 않는다. 주변 차량과 자차의 상태를 분석하여 플래툰 참여 여부, 리더·팔로워 역할, 목표 속도 및 목표 차간거리를 결정하고 이를 주행 알고리즘에 전달하는 상위 의사결정 알고리즘이다.

```text
V2X 통신 ── 주변 차량 정보 ──┐
                              ├─> 플래툰 알고리즘
주행 알고리즘 ─ 자차 주행 정보 ┘          │
                                         ├─ 주행 모드
                                         ├─ 목표 속도
                                         ├─ 목표 차간거리
                                         └─ 추종 차량 ID
                                               │
                                               v
                                        주행 알고리즘
                                               │
                                               v
                                        STM32 차량 제어
```

### 기능별 책임

| 구성 | 주요 역할 |
|---|---|
| V2X 통신 | 주변 차량 정보 브로드캐스트 및 플래툰 차량 간 전용 정보 교환 |
| UWB | 상대 차량의 거리와 각도 측정 및 차량 ID 매칭 보조 |
| 플래툰 알고리즘 | 후보 선별, 적합도 계산, 결합 판단, 역할 결정 및 목표값 생성 |
| 주행 알고리즘 | 차선 인식, 장애물 대응, 목표 속도와 거리 추종 |
| STM32 | 모터 PID 및 서보 조향 등 실제 구동 제어 |

## 4. 전체 알고리즘 흐름

```text
① 일반 V2X 통신으로 주변 차량 정보를 수신한다.
② 자차 주행 알고리즘에서 현재 주행 정보를 받아온다.
③ 같은 도로·방향에 있으며 합류 가능한 차량을 선별한다.
④ 후보 차량별 플래툰 절대조건을 검사한다.
⑤ 절대조건을 통과한 차량의 플래툰 적합도를 계산한다.
⑥ 가장 높은 점수의 차량이 기준점수를 넘는지 판단한다.
⑦ 기준점수를 넘으면 해당 차량에 결합을 요청한다.
⑧ 상대 차량도 조건과 적합도를 확인하여 승인 또는 거절한다.
⑨ 양쪽이 동의하면 플래툰 ID와 리더·팔로워 역할을 결정한다.
⑩ 플래툰 전용 유니캐스트 통신을 설정한다.
⑪ 리더와 팔로워가 속도 및 차간거리를 조정하며 결합한다.
⑫ 거리와 속도가 안정되면 결합 완료를 확인한다.
⑬ 플래툰 주행 상태로 전환한다.
```

## 5. 주변 차량 1차 선별

V2X로 탐색된 모든 차량이 플래툰 후보가 되는 것은 아니다. 다음 정보를 이용하여 현재 도로에서 실제로 합류할 수 있는 차량만 1차 선별한다.

- 현재 체크포인트가 같거나 인접한가?
- 다음 체크포인트가 같아 동일 방향으로 주행하는가?
- 동일 차선이거나 합류할 수 있는 차선인가?
- UWB 측정 거리 안에 존재하는가?
- 상대 차량이 자차의 앞쪽인지 뒤쪽인지 확인할 수 있는가?

1차 선별은 연산 대상 차량 수를 줄이기 위한 과정이며, 최종 결합 여부는 절대조건과 적합도 점수로 결정한다.

## 6. 플래툰 절대조건

절대조건은 점수로 보완할 수 없는 필수 조건이다. 하나라도 만족하지 않으면 적합도를 계산하지 않고 해당 차량을 후보에서 제외한다.

\[
C_{\mathrm{join}}
=C_P\land C_R\land C_H\land C_D\land C_S
\]

| 조건 | 의미 |
|---|---|
| \(C_P\) | 두 차량 모두 플래툰 참여를 허용했는가? |
| \(C_R\) | 예정 경로가 최소 기준 이상 연속해서 겹치는가? |
| \(C_H\) | 같은 도로에서 같은 방향으로 주행하는가? |
| \(C_D\) | 통신 및 합류 가능한 최대거리 이내인가? |
| \(C_S\) | 두 차량 모두 긴급·고장 상태가 아닌가? |

### 조건식

\[
C_P=(P_i=1)\land(P_j=1)
\]

\[
C_R=L_{\mathrm{overlap}}\ge L_{\min}
\]

\[
C_H=|\theta_i-\theta_j|\le\theta_{\max}
\]

\[
C_D=d_{ij}\le d_{\max}
\]

\[
C_S=(E_i=0)\land(E_j=0)
\]

### 초기 기준값 예시

| 기준 | 초기 설정 예시 |
|---|---:|
| 최소 경로 중첩 | 연속 체크포인트 2개 이상 |
| 최대 진행 방향 차이 | 30° |
| 최대 후보 거리 | 5 m |
| 플래툰 참여 허용 | 양쪽 차량 모두 TRUE |
| 긴급·고장 상태 | 양쪽 차량 모두 FALSE |

위 수치는 알고리즘 구조를 검증하기 위한 초기값이며 실제 맵 크기, 차량 속도 및 UWB 측정 범위에 따라 조정한다.

## 7. 플래툰 적합도 계산

절대조건을 모두 통과한 후보 차량에 대해서만 0~1 범위의 적합도를 계산한다.

\[
S_{\mathrm{platoon}}
=w_dS_d+w_rS_r+w_vS_v+w_qS_q+w_aS_a
\]

\[
w_d+w_r+w_v+w_q+w_a=1
\]

### 초기 가중치

| 평가 요소 | 점수 | 가중치 |
|---|---:|---:|
| 차량 간 거리 | \(S_d\) | 0.25 |
| 경로 중첩 | \(S_r\) | 0.35 |
| 속도 유사도 | \(S_v\) | 0.20 |
| 통신 품질 | \(S_q\) | 0.10 |
| 상대 방향·각도 | \(S_a\) | 0.10 |

경로가 충분히 겹쳐야 플래툰을 오래 유지할 수 있으므로 경로 중첩에 가장 높은 가중치를 둔다.

### 7.1 차량 간 거리 점수

\[
S_d=
\begin{cases}
0, & d_{ij}<d_{\mathrm{safe}}\\
1-\dfrac{d_{ij}-d_{\mathrm{safe}}}{d_{\max}-d_{\mathrm{safe}}},
& d_{\mathrm{safe}}\le d_{ij}\le d_{\max}\\
0, & d_{ij}>d_{\max}
\end{cases}
\]

안전거리보다 가깝거나 최대 합류거리보다 먼 차량은 거리 점수를 0으로 한다. 안전거리 이상이면서 가까운 차량일수록 높은 점수를 받는다.

### 7.2 경로 중첩 점수

\[
S_r=\frac{L_{\mathrm{overlap}}}{\min(L_i,L_j)}
\]

체크포인트 방식에서는 다음과 같이 계산할 수 있다.

\[
S_r=\frac{N_{\mathrm{common}}}{\min(N_i,N_j)}
\]

공통 체크포인트는 단순 포함 개수가 아니라 현재 위치 이후에 동일한 순서로 연속해서 겹치는 구간을 사용한다.

### 7.3 속도 유사도 점수

\[
S_v=\max\left(0,1-\frac{|v_i-v_j|}{\Delta v_{\max}}\right)
\]

속도 차이가 작을수록 적은 가감속으로 결합할 수 있으므로 높은 점수를 부여한다.

### 7.4 통신 품질 점수

\[
S_q=\alpha S_{\mathrm{PDR}}+(1-\alpha)S_{\mathrm{RSSI}}
\]

\[
S_{\mathrm{PDR}}=\frac{N_{\mathrm{received}}}{N_{\mathrm{expected}}}
\]

초기에는 패킷 수신율을 더 중요하게 반영하도록 \(\alpha=0.7\) 정도로 설정할 수 있다.

### 7.5 상대 방향·각도 점수

\[
S_a=\max\left(0,1-\frac{|\theta_i-\theta_j|}{\theta_{\max}}\right)
\]

두 차량의 진행 방향이 같을수록 높은 점수를 부여한다. UWB AoA는 상대 차량의 앞뒤 위치 판단에도 이용한다.

## 8. 최종 결합 판단

절대조건과 적합도 기준을 모두 만족해야 결합 절차를 시작한다.

\[
J_{ij}=C_{\mathrm{join}}\land
\left(S_{\mathrm{platoon}}\ge T_{\mathrm{join}}\right)
\]

초기 결합 기준점수는 다음과 같이 설정한다.

\[
T_{\mathrm{join}}=0.70
\]

| 적합도 | 판단 |
|---:|---|
| \(S<0.50\) | 플래툰 부적합 |
| \(0.50\le S<0.70\) | 결합하지 않고 재평가 |
| \(S\ge0.70\) | 플래툰 결합 요청 가능 |

순간적인 측정값으로 결합하는 것을 방지하기 위해 최근 5회의 평가 중 4회 이상 기준을 통과한 경우에만 결합 요청을 전송한다.

\[
N_{\mathrm{pass}}\ge4 \quad \text{within 5 evaluations}
\]

적합도 통과는 플래툰 결합 완료가 아니라 **결합 절차를 시작하는 조건**이다.

### 후보가 여러 대인 경우

\[
j^*=\arg\max_j S_{\mathrm{platoon}}(i,j)
\]

절대조건을 만족한 차량 중 적합도가 가장 높은 차량을 선택한다. 점수가 같거나 매우 비슷한 경우 다음 순서로 우선순위를 적용한다.

1. 경로 중첩이 긴 차량
2. 속도 차이가 작은 차량
3. 통신 품질이 높은 차량
4. 차량 ID가 작은 차량

## 9. 일반 V2X와 플래툰 전용 통신

### 9.1 일반 V2X 통신

- 주변의 모든 차량을 대상으로 브로드캐스트한다.
- 차량 ID, 경로, 속도, 목적지 및 플래툰 허용 상태를 공유한다.
- 주변 차량 탐색과 적합도 평가에 사용한다.

### 9.2 플래툰 전용 통신

- 결합 대상으로 선택된 차량 사이에서 유니캐스트로 수행한다.
- 플래툰 ID를 이용해 다른 차량의 패킷을 필터링한다.
- 일반 V2X보다 짧은 주기로 속도·가속도·차간거리 정보를 교환한다.
- 별도의 무선장치를 의미하는 것이 아니라 ESP-NOW 통신 안에서 논리적으로 구분할 수 있다.

| 전용 통신 데이터 | 용도 |
|---|---|
| 플래툰 ID | 같은 플래툰 차량 식별 |
| 리더·팔로워 ID | 역할과 통신 대상 지정 |
| 현재·목표 속도 | 속도 동기화 |
| 가속도·감속 상태 | 리더의 움직임 전달 |
| 현재·목표 차간거리 | 팔로워 거리 제어 |
| 결합 진행 상태 | 접근·안정화·완료 상태 공유 |
| 긴급 정지 정보 | 즉각적인 안전 제어 |
| 순서번호·타임스탬프 | 패킷 누락 및 최신성 판단 |

## 10. 플래툰 결합 통신 절차

| 순서 | 송신 차량 | 메시지 | 주요 내용 |
|---:|---|---|---|
| 1 | 요청 차량 | `JOIN_REQUEST` | 적합도와 결합 요청 전송 |
| 2 | 상대 차량 | `JOIN_ACCEPT` 또는 `JOIN_REJECT` | 자체 조건 재검사 후 응답 |
| 3 | 두 차량 | `PLATOON_SETUP` | 플래툰 ID와 역할 공유 |
| 4 | 리더 | `MERGE_COMMAND` | 목표 속도와 목표 차간거리 전달 |
| 5 | 팔로워 | `MERGE_STATUS` | 현재 거리와 결합 진행 상태 전달 |
| 6 | 두 차량 | `JOIN_COMPLETE` | 결합 완료 확인 |
| 7 | 두 차량 | `PLATOON_CONTROL` | 플래툰 주행정보 주기적 교환 |

### 10.1 결합 요청

적합도가 기준을 통과한 차량이 선택된 상대 차량에 `JOIN_REQUEST`를 전송한다.

```c
typedef struct {
    uint8_t  msg_type;          // JOIN_REQUEST
    uint16_t requester_id;      // 요청 차량 ID
    uint16_t target_id;         // 상대 차량 ID
    uint8_t  suitability;       // 적합도: 0~100
    uint16_t checkpoint_id;     // 현재 체크포인트
    uint16_t destination_id;    // 목적지
    float    speed;             // 현재 속도
    float    distance;          // 차량 간 거리
    uint32_t timestamp;
} PlatoonJoinRequest;
```

### 10.2 상대 차량 재검사

상대 차량은 요청 수신 후 자신의 데이터로 다음을 다시 검사한다.

1. 요청 및 대상 차량 ID 확인
2. 현재 플래툰 참여 허용 여부 확인
3. 다른 결합 절차가 진행 중인지 확인
4. 경로, 방향 및 거리 재확인
5. 자체 적합도 계산
6. 승인 또는 거절 전송

양쪽 차량이 모두 기준을 통과해야 결합한다.

\[
C_{\mathrm{agreement}}=J_{ij}\land J_{ji}
\]

### 10.3 플래툰 ID와 역할 결정

승인 후 플래툰 ID를 생성하고 두 차량이 공유한다. 기본적으로 진행 방향의 앞쪽 차량을 리더, 뒤쪽 차량을 팔로워로 결정한다.

```text
상대 차량이 자차 앞쪽 → 상대 차량 리더, 자차 팔로워
상대 차량이 자차 뒤쪽 → 자차 리더, 상대 차량 팔로워
```

앞뒤 관계가 불분명하면 다음 순서를 적용한다.

1. UWB AoA와 진행 방향 기준 앞쪽 차량
2. 다음 체크포인트를 먼저 통과한 차량
3. 속도가 더 안정적인 차량
4. 차량 ID가 작은 차량

플래툰 ID는 리더 ID와 순서번호를 결합하는 단순한 방식으로 시작할 수 있다.

```text
Platoon ID = Leader ID + Platoon Sequence
```

## 11. 두 차량의 실제 결합

### 11.1 목표 차간거리

속도에 따라 목표 차간거리를 설정하려면 다음 식을 사용할 수 있다.

\[
d_{\mathrm{target}}=d_0+T_hv_f
\]

- \(d_0\): 정지 상태 최소거리
- \(T_h\): 목표 시간 간격
- \(v_f\): 팔로워 속도

초기 구현에서는 고정 목표거리로 단순화할 수 있다.

```text
목표 차간거리: 0.8 m
결합 허용범위: 0.7~0.9 m
```

### 11.2 팔로워 목표속도

\[
v_{\mathrm{target}}
=v_{\mathrm{leader}}
+K_d(d-d_{\mathrm{target}})
+K_v(v_{\mathrm{leader}}-v_{\mathrm{follower}})
\]

- 현재 거리가 목표보다 멀면 팔로워를 가속한다.
- 현재 거리가 목표보다 가까우면 팔로워를 감속한다.
- 리더와 팔로워의 속도 차이도 함께 보정한다.

플래툰 알고리즘은 다음 목표값을 주행 알고리즘으로 전달한다.

```text
주행 모드       : PLATOON_MERGE
목표 차량 ID    : Leader ID
목표 속도       : 계산된 팔로워 목표속도
목표 차간거리   : d_target
가감속 요청     : ACCELERATE / HOLD / DECELERATE
```

### 11.3 결합 완료 조건

차간거리와 속도 차이가 모두 허용범위 안에서 일정 시간 유지되어야 결합 완료로 판단한다.

\[
C_{\mathrm{complete}}
=|d-d_{\mathrm{target}}|\le\epsilon_d
\land |v_l-v_f|\le\epsilon_v
\]

초기 조건 예시는 다음과 같다.

```text
차간거리 오차  ≤ 0.1 m
차량 속도 차이 ≤ 0.1 m/s
조건 유지시간  ≥ 1초
전용 통신 상태 = 정상
```

조건이 유지되면 양쪽 차량이 `JOIN_COMPLETE`를 교환하고 `PLATOON_FOLLOW` 상태로 진입한다.

## 12. 상태 기반 알고리즘

| 상태 | 의미 | 다음 상태 조건 |
|---|---|---|
| `V2X_SEARCH` | 일반 V2X로 주변 차량 탐색 | 후보 차량 발견 |
| `EVALUATE` | 절대조건과 적합도 계산 | 점수 통과 또는 미달 |
| `JOIN_REQUEST` | 선택 차량에 결합 요청 | 승인 또는 거절 |
| `PLATOON_SETUP` | 플래툰 ID·역할·전용 통신 설정 | 설정 완료 |
| `MERGING` | 속도와 차간거리 조정 | 거리·속도 안정 |
| `PLATOON_FOLLOW` | 플래툰 결합 완료 및 추종 주행 | 후속 해제 조건 |

```text
V2X_SEARCH
    └─ 후보 발견 → EVALUATE
                       ├─ 점수 미달 → V2X_SEARCH
                       └─ 점수 통과 → JOIN_REQUEST
                                           ├─ 거절 → V2X_SEARCH
                                           └─ 승인 → PLATOON_SETUP
                                                          └─ 설정 완료 → MERGING
                                                                            └─ 안정화 → PLATOON_FOLLOW
```

## 13. 통합 수도코드

```c
Candidate best = { .valid = false, .score = 0.0f };

for (each vehicle in v2x_vehicle_list) {

    // 1차 선별 및 절대조건
    if (!vehicle.platoon_allow)             continue;
    if (vehicle.emergency)                  continue;
    if (!is_same_road_and_direction(vehicle)) continue;
    if (vehicle.distance > MAX_JOIN_DISTANCE) continue;

    route_overlap = calculate_route_overlap(
        ego.route,
        vehicle.route
    );

    if (route_overlap < MIN_ROUTE_OVERLAP)  continue;

    // 적합도 계산
    distance_score = calculate_distance_score(vehicle.distance);
    route_score    = calculate_route_score(ego.route, vehicle.route);
    speed_score    = calculate_speed_score(ego.speed, vehicle.speed);
    comm_score     = calculate_comm_score(vehicle.pdr, vehicle.rssi);
    angle_score    = calculate_angle_score(ego.heading, vehicle.heading);

    total_score =
          0.25f * distance_score
        + 0.35f * route_score
        + 0.20f * speed_score
        + 0.10f * comm_score
        + 0.10f * angle_score;

    if (total_score > best.score) {
        best.vehicle_id = vehicle.vehicle_id;
        best.score      = total_score;
        best.valid      = true;
    }
}

// 결합 절차 시작 판단
if (best.valid &&
    best.score >= JOIN_THRESHOLD &&
    is_score_stable(best.vehicle_id)) {

    send_join_request(best.vehicle_id, best.score);
    platoon_state = JOIN_REQUEST;

} else {
    platoon_state = V2X_SEARCH;
}

// 상대 차량 승인 후
if (receive_join_accept(best.vehicle_id)) {
    decide_leader_and_follower();
    create_and_share_platoon_id();
    configure_platoon_unicast();
    platoon_state = PLATOON_SETUP;
}

// 차량 결합
while (platoon_state == MERGING) {
    target_speed = calculate_merge_speed(
        leader_speed,
        follower_speed,
        uwb_distance,
        target_distance
    );

    send_to_driving_algorithm(
        PLATOON_MERGE,
        target_speed,
        target_distance,
        leader_id
    );

    send_merge_status();

    if (is_distance_stable() &&
        is_speed_stable() &&
        is_stable_for_required_time()) {

        send_join_complete();
        platoon_state = PLATOON_FOLLOW;
    }
}
```

## 14. 현재까지 확정된 내용

- 일반 V2X 브로드캐스트로 주변 차량 정보를 탐색한다.
- 자차 주행 정보와 주변 차량 정보를 함께 사용한다.
- 필수 안전·경로 조건은 절대조건으로 먼저 검사한다.
- 절대조건을 통과한 차량만 0~1 범위의 적합도를 계산한다.
- 초기 결합 기준점수는 0.70으로 설정한다.
- 한 번의 점수보다 최근 5회 중 4회 통과 여부를 사용한다.
- 여러 후보 중 가장 높은 점수의 차량을 선택한다.
- 점수 통과는 결합 완료가 아니라 `JOIN_REQUEST` 시작 조건이다.
- 상대 차량도 자체 조건을 재검사하고 승인해야 한다.
- 승인 후 플래툰 ID와 리더·팔로워 역할을 결정한다.
- 전용 통신은 ESP-NOW 유니캐스트와 플래툰 ID 필터링으로 구성한다.
- 실제 결합 단계에서는 목표 속도와 목표 차간거리를 주행 알고리즘에 전달한다.
- 거리와 속도가 안정되면 결합 완료 후 플래툰 주행으로 전환한다.

# 플래툰 결합 이후 주행 알고리즘

## 17. 결합 이후 전체 상태 구조

플래툰 적합도 계산과 상호 승인이 완료되면 실제 차량 결합과 주행을 다음 세 가지 핵심 상태로 관리한다.

| 상태 | 역할 |
|---|---|
| `PLATOON_JOIN` | 두 차량의 차선, 거리 및 속도를 맞추어 실제 플래툰을 형성 |
| `PLATOON_MAINTAIN` | 목표 차간거리를 유지하며 플래툰 목적지까지 주행 |
| `PLATOON_EXIT` | 차량 사이의 거리를 벌리고 플래툰을 해제 |

전체 상태 전환은 다음과 같다.

```text
SOLO_DRIVE
    │ 적합도 통과 및 상호 승인
    v
PLATOON_JOIN
    │ 차선·거리·속도 안정
    v
PLATOON_MAINTAIN
    │ 목적지 접근 또는 정상 해제 요청
    v
PLATOON_EXIT
    │ 안전한 분리거리 확보
    v
SOLO_DRIVE
```

플래툰 유지 중 새로운 차량이 승인되면 기존 플래툰은 유지하면서 신규 차량에 대해 `PLATOON_JOIN` 절차를 추가로 수행한다.

---

## 18. 플래툰 통신 모드 변경

플래툰 결합이 승인되면 플래툰 알고리즘은 ESP32에 고속 전용 통신으로 변경하도록 명령한다. ESP32 내부의 구체적인 제어 알고리즘은 이후 단계에서 설계한다.

```text
V2X_MODE    = PLATOON_HIGH_RATE
PLATOON_ID  = 생성된 플래툰 ID
TARGET_IDS  = 같은 플래툰 차량 ID 목록
```

플래툰 전용 통신은 별도의 무선장치를 추가하는 것이 아니라 ESP-NOW 통신을 논리적으로 구분하여 사용할 수 있다.

| 통신 종류 | 대상 | 초기 주기 예시 | 목적 |
|---|---|---:|---|
| 일반 V2X 탐색 | 주변 모든 차량 | 200~500 ms | 주변 차량 및 신규 후보 탐색 |
| 플래툰 전용 통신 | 같은 플래툰 차량 | 20~50 ms | 속도·가속도·거리·상태 교환 |
| 긴급 메시지 | 같은 플래툰 차량 | 즉시 | 급정지·장애물·강제 해제 전달 |

플래툰 주행 중에도 일반 V2X 브로드캐스트는 중단하지 않는다.

```text
빠른 주기 → 현재 플래툰 차량과 전용 유니캐스트 통신
느린 주기 → 일반 V2X 브로드캐스트로 주변 차량 탐색
```

## 19. PLATOON_JOIN 상태

`PLATOON_JOIN`은 통신상 결합이 승인된 차량들이 실제 도로에서 같은 차선으로 정렬하고 목표 차간거리와 속도를 형성하는 과정이다.

### 19.1 JOIN 내부 단계

차선 변경과 거리 조정을 한 번에 수행하지 않고 다음과 같이 세분화한다.

```text
JOIN_REQUESTED
    → JOIN_LANE_ALIGN
    → JOIN_GAP_CONTROL
    → JOIN_STABILIZE
    → PLATOON_MAINTAIN
```

| 내부 상태 | 수행 내용 | 완료 조건 |
|---|---|---|
| `JOIN_REQUESTED` | 역할·목표 차선·목표거리 공유 | 모든 차량 설정 확인 |
| `JOIN_LANE_ALIGN` | 팔로워를 목표 차선으로 이동 | 동일 차선 및 중앙 정렬 |
| `JOIN_GAP_CONTROL` | 리더 감속·팔로워 가속으로 거리 조절 | 목표거리 허용범위 진입 |
| `JOIN_STABILIZE` | 동일 속도와 차간거리 안정 확인 | 일정 시간 동안 조건 유지 |

도로 상황에 따라 먼저 안전한 차선 변경 간격을 만든 후 차선을 변경해야 할 수 있으므로 주행 알고리즘의 차선 변경 가능 응답을 확인해야 한다.

### 19.2 리더와 팔로워

기본적으로 진행 방향의 앞쪽 차량을 리더, 뒤쪽 차량을 팔로워로 한다.

```text
앞쪽 차량 = Leader
뒤쪽 차량 = Follower
```

앞뒤 관계는 UWB AoA, 진행 방향, 현재 체크포인트 및 체크포인트 통과 순서를 함께 사용하여 판단한다.

### 19.3 목표 차선 결정

초기 구현에서는 리더의 현재 차선을 플래툰 목표 차선으로 지정한다.

```text
Target Lane = Leader Current Lane
```

팔로워가 다른 차선에 있으면 플래툰 알고리즘은 주행 알고리즘에 다음 명령을 전달한다.

```text
Mode           = PLATOON_JOIN
Target Lane    = Leader Lane
Target Vehicle = Leader ID
Lane Change    = REQUEST
```

실제 차선 변경 전에는 주행 알고리즘에서 다음 조건을 확인한다.

- 목표 차선에 장애물이 없는가?
- 다른 차량과 충돌 위험이 없는가?
- 차선 변경이 가능한 도로 구간인가?
- 상대 차량의 위치와 속도가 안정적인가?

### 19.4 차선 정렬 완료 조건

\[
C_{\mathrm{lane\_complete}}
=(L_F=L_L)
\land |e_{\mathrm{lane}}|\le e_{\max}
\land t_{\mathrm{stable}}\ge t_{\min}
\]

- 리더와 팔로워의 차선 ID가 동일해야 한다.
- 카메라 기반 차선 중앙 오프셋이 허용범위 이내여야 한다.
- 정렬 상태가 일정 시간 유지되어야 한다.

명령과 실제 완료 상태는 구분해야 한다.

```text
플래툰 알고리즘 → 주행 알고리즘: LANE_CHANGE_REQUEST
주행 알고리즘 → 플래툰 알고리즘: LANE_CHANGE_ACCEPT
주행 알고리즘 → 플래툰 알고리즘: LANE_CHANGE_RUNNING
주행 알고리즘 → 플래툰 알고리즘: LANE_CHANGE_COMPLETE
```

### 19.5 차간거리 조정

현재 차간거리를 \(d\), 목표 차간거리를 \(d_{\mathrm{target}}\)이라 하면 거리 오차는 다음과 같다.

\[
e_d=d-d_{\mathrm{target}}
\]

목표거리보다 멀면 앞차는 제한된 범위에서 감속하고 뒤차는 제한된 범위에서 가속한다.

\[
v_{L,\mathrm{join}}=v_{\mathrm{base}}-K_Le_d
\]

\[
v_{F,\mathrm{join}}=v_{\mathrm{base}}+K_Fe_d
\]

단, 목표속도와 가속도는 다음 범위로 제한한다.

\[
v_{\min}\le v_{\mathrm{target}}\le v_{\max}
\]

\[
|a_{\mathrm{command}}|\le a_{\max}
\]

두 차량의 접근속도는 다음과 같다.

\[
v_{\mathrm{closing}}=v_F-v_L
\]

리더 감속과 팔로워 가속을 동시에 크게 적용하면 접근속도가 과도해질 수 있으므로 다음 순서를 권장한다.

```text
1. 리더가 결합 기준속도로 완만하게 감속한다.
2. 팔로워가 제한된 접근속도로 거리를 줄인다.
3. 목표거리 근처에서 두 차량을 같은 속도로 동기화한다.
```

| 거리 상태 | 리더 동작 | 팔로워 동작 |
|---|---|---|
| 목표거리보다 매우 멂 | 완만한 감속 | 제한된 가속 |
| 목표거리에 접근 중 | 기준속도로 복귀 | 접근속도 감소 |
| 목표거리 범위 도달 | 속도 유지 | 리더 속도 추종 |
| 목표거리보다 가까움 | 필요 시 완만한 가속 | 감속 |

초기 안전 제한값의 예시는 다음과 같으며 실차시험으로 확정한다.

```text
최대 접근속도        = 0.3 m/s
한 주기 속도 변화량  = 0.05 m/s 이하
목표거리 근접구간    = 목표거리 + 0.3 m
```

### 19.6 거리 센서 사용

| 거리 정보 | 주요 역할 |
|---|---|
| UWB | 차량 ID 매칭 및 JOIN 초기 중·장거리 측정 |
| 초음파 센서 | 동일 차선에서 가까운 앞차의 안전거리 측정 |
| V2X 주행정보 | 상대속도와 위치 변화 예측 |

권장 적용 순서는 다음과 같다.

```text
JOIN 초기 접근 → UWB 중심
목표거리 근접  → UWB와 초음파 비교
MAINTAIN       → 초음파 중심, UWB 보조
```

### 19.7 JOIN 완료 조건

\[
C_{\mathrm{join\_complete}}
=C_{\mathrm{lane}}
\land C_{\mathrm{distance}}
\land C_{\mathrm{speed}}
\land C_{\mathrm{time}}
\]

초기 완료 조건은 다음과 같이 설정할 수 있다.

```text
동일 차선                  = TRUE
|현재 거리 - 목표거리|     ≤ 0.1 m
|리더 속도 - 팔로워 속도|  ≤ 0.1 m/s
안정 상태 유지시간         ≥ 1초
플래툰 전용 통신           = 정상
```

조건을 만족하면 양쪽 차량이 `JOIN_COMPLETE`를 교환하고 `PLATOON_MAINTAIN` 상태로 전환한다.

## 20. PLATOON_MAINTAIN 상태

`PLATOON_MAINTAIN`에서는 같은 차선에서 목표 차간거리를 유지하며 공통 경로의 플래툰 목적지까지 주행한다.

### 20.1 리더 동작

리더는 도로와 장애물 상황을 기반으로 기준속도를 결정하고 다음 정보를 짧은 주기로 전송한다.

- 현재 및 목표 속도
- 현재 가속도와 제동 상태
- 현재 및 다음 체크포인트
- 플래툰 목적지까지 남은 체크포인트 수
- 장애물 및 긴급 상태
- 플래툰 구성과 상태

### 20.2 팔로워 동작

팔로워는 리더의 상태를 피드포워드로 사용하고 실제 차간거리 및 상대속도를 피드백하여 목표속도를 계산한다.

\[
v_{F,\mathrm{target}}
=v_L
+K_d(d-d_{\mathrm{target}})
+K_v(v_L-v_F)
\]

- 리더가 가속하면 팔로워도 가속한다.
- 리더가 감속하면 팔로워도 감속한다.
- 차간거리가 벌어지면 팔로워 속도를 소폭 높인다.
- 차간거리가 좁아지면 팔로워 속도를 낮춘다.

플래툰 알고리즘은 다음 값을 주행 알고리즘으로 전달한다.

```text
Mode            = PLATOON_MAINTAIN
Leader ID       = 추종 대상 차량 ID
Target Speed    = 계산된 팔로워 목표속도
Target Distance = 목표 차간거리
Target Lane     = 플래툰 주행 차선
```

실제 적용 전 다음 값을 결정해야 한다.

- 거리 제어 이득 \(K_d\)
- 상대속도 제어 이득 \(K_v\)
- 제어 계산 주기
- 목표속도 상·하한
- 한 주기당 최대 속도 변화량

### 20.3 목표 차간거리

속도에 따라 목표 차간거리를 조절하려면 다음 식을 사용한다.

\[
d_{\mathrm{target}}=d_0+T_hv_F
\]

초기 구현에서는 고정 차간거리로 시작한 뒤 속도 기반 방식으로 확장한다.

```text
초기 목표 차간거리 = 0.8 m
차간거리 허용범위  = 0.7~0.9 m
```

### 20.4 플래툰 목적지 정의

플래툰 목적지는 단순히 한 차량의 최종 목적지가 아니라 참여 차량들의 예정 경로가 마지막으로 공통되는 체크포인트를 기준으로 한다.

> 플래툰 목적지: 참여 차량의 공통 경로가 끝나는 마지막 체크포인트

실제 EXIT는 분기 지점에서 바로 시작하지 않고 이전 체크포인트 또는 일정 거리 전에 시작한다.

```text
공통 경로           = CP03 → CP04 → CP05 → CP06
플래툰 목적지       = CP06
EXIT 시작 체크포인트 = CP05
```

### 20.5 체크포인트 카운트

플래툰 결합 시 공통 경로와 EXIT 시작점을 저장한다.

```text
Platoon Route       = [CP03, CP04, CP05, CP06]
Platoon Destination = CP06
Exit Start Point    = CP05
```

현재 체크포인트가 예정된 다음 체크포인트와 일치할 때만 인덱스를 증가시킨다.

```c
if (current_checkpoint ==
    platoon_route[next_checkpoint_index]) {

    next_checkpoint_index++;
    remaining_checkpoints--;
}
```

단순히 숫자를 감소시키는 것이 아니라 체크포인트 순서가 계획된 경로와 일치하는지 확인해야 한다.

### 20.6 주변 차량 지속 탐색

플래툰 유지 중에도 일반 V2X 통신을 통해 주변 차량을 계속 탐색한다.

```text
PLATOON_CONTROL → 기존 플래툰 차량과 빠른 정보 교환
V2X_BEACON      → 주변 차량을 느린 주기로 지속 탐색
```

신규 차량이 발견되면 다음 절차를 수행한다.

```text
신규 차량 발견
→ 절대조건 검사
→ 기존 플래툰 공통 경로와 적합도 계산
→ 기준점수 통과
→ 가입 요청 및 승인
→ 신규 차량에 대해 PLATOON_JOIN 수행
→ PLATOON_MAINTAIN 복귀
```

초기 구현에서는 신규 차량을 플래툰의 맨 뒤에만 합류시킨다. 중간 삽입은 여러 차량이 동시에 간격을 조정해야 하므로 이후 확장 기능으로 둔다.

### 20.7 다중 차량 추종 구조

3대 이상에서는 리더 정보를 모든 차량이 수신하되 각 팔로워는 바로 앞 차량과의 실제 차간거리를 유지한다.

```text
Vehicle 1: Leader
Vehicle 2: Vehicle 1 추종
Vehicle 3: Vehicle 2 추종
Vehicle 4: Vehicle 3 추종
```

다중 차량 패킷에 추가로 필요한 정보는 다음과 같다.

- 플래툰 내 순번
- 앞 차량 ID
- 뒤 차량 ID
- 전체 참여 차량 수
- 플래툰 구성 버전

## 21. PLATOON_EXIT 상태

`PLATOON_EXIT`에서는 목적지 또는 경로 분기 이전에 차량 사이의 거리를 안전하게 벌린 뒤 플래툰을 해제한다.

### 21.1 EXIT 진입 조건

체크포인트 기반 조건은 다음과 같다.

\[
C_{\mathrm{exit}}=N_{\mathrm{remaining}}\le N_{\mathrm{exit}}
\]

또는 목적지까지의 실제 거리를 사용할 수 있다.

\[
D_{\mathrm{destination}}\le D_{\mathrm{exit}}
\]

초기 구현에서는 공통 경로의 마지막 체크포인트보다 하나 앞선 체크포인트에서 EXIT를 시작한다.

### 21.2 EXIT 통신 절차

```text
Leader   → EXIT_REQUEST
Follower → EXIT_ACK
Leader   → EXIT_START
```

EXIT 패킷에는 다음 정보가 필요하다.

- 플래툰 ID
- 해제 대상 차량 ID
- 해제 시작 체크포인트
- 해제 시작 시각
- 목표 분리거리
- 해제 후 주행 모드 및 개별 경로

### 21.3 차량 간격 확대

두 대 기준으로 리더는 제한된 범위에서 가속하고 팔로워는 제한된 범위에서 감속한다.

\[
e_{\mathrm{exit}}=d_{\mathrm{release}}-d
\]

\[
v_{L,\mathrm{exit}}=v_{\mathrm{base}}+K_{EL}e_{\mathrm{exit}}
\]

\[
v_{F,\mathrm{exit}}=v_{\mathrm{base}}-K_{EF}e_{\mathrm{exit}}
\]

- \(d_{\mathrm{release}}\): 플래툰 해제 완료 거리
- \(d\): 현재 차량 간 거리

JOIN과 마찬가지로 최대속도, 최소속도 및 가속도 제한을 적용한다.

### 21.4 EXIT 완료 조건

\[
C_{\mathrm{exit\_complete}}
=d\ge d_{\mathrm{release}}
\land C_{\mathrm{stable}}
\]

초기 완료 조건 예시는 다음과 같다.

```text
차량 간 거리        ≥ 2.0 m
분리 상태 유지시간  ≥ 1초
차선 변경 가능 상태 = TRUE
```

완료 후 다음 순서로 단독주행에 복귀한다.

```text
1. PLATOON_EXIT_COMPLETE 교환
2. 플래툰 ID와 차량 역할 삭제
3. 전용 고속 통신 종료
4. 일반 V2X 통신 주기로 복귀
5. 주행 알고리즘에 SOLO_DRIVE 전달
6. 각 차량의 개별 목적지 경로로 복귀
```

차량이 3대 이상이면 동시에 전체를 분리하지 않고 마지막 팔로워부터 순차적으로 해제한다.

```text
마지막 팔로워 해제
→ 다음 팔로워 해제
→ 최종적으로 리더 단독주행
```

## 22. 상태별 주행 알고리즘 출력

| 플래툰 상태 | 주행 모드 | 주요 출력 |
|---|---|---|
| `PLATOON_JOIN` | 결합 주행 | 목표 차선, 목표 속도, 목표 차간거리, 대상 차량 ID |
| `PLATOON_MAINTAIN` | 추종 주행 | 리더 ID, 추종 속도, 유지 차간거리, 목표 차선 |
| `PLATOON_EXIT` | 분리 주행 | 분리 목표속도, 해제거리, 개별 목적지 경로 |
| `SOLO_DRIVE` | 단독주행 | 자차 원래 경로와 정상 주행속도 |

`차선거리`라는 표현보다 차량 사이의 거리를 의미하는 **차간거리**로 표현한다. 차선은 동일 차선으로 정렬하고 차량 사이에서는 목표 차간거리를 유지한다.

## 23. 결합 이후 통합 알고리즘

```text
① 플래툰 적합도와 상호 승인을 통해 결합 대상을 확정한다.

② ESP32에 플래툰 전용 고속 통신 설정을 요청한다.

③ 플래툰 ID와 리더·팔로워 역할을 참여 차량에 전달한다.

④ PLATOON_JOIN 상태로 진입한다.

⑤ 팔로워가 리더 차선으로 이동하도록 주행 알고리즘에 요청한다.

⑥ 차선 변경 완료 응답과 차선 중앙 정렬 상태를 확인한다.

⑦ 리더는 완만하게 감속하고 팔로워는 제한된 범위에서 가속하여
   목표 차간거리로 접근한다.

⑧ 목표거리 근처에서 두 차량의 속도를 동일하게 맞춘다.

⑨ 동일 차선, 거리 및 속도가 일정 시간 안정되면
   PLATOON_MAINTAIN 상태로 전환한다.

⑩ 리더 정보와 실제 차간거리를 이용하여 팔로워 목표속도를 계산한다.

⑪ 플래툰 목적지까지 남은 체크포인트를 예정 경로 순서대로 갱신한다.

⑫ 플래툰 주행 중에도 일반 V2X 탐색을 유지하여
   주변 차량 정보와 신규 가입 요청을 처리한다.

⑬ 신규 차량이 기준을 통과하면 플래툰 맨 뒤에서 JOIN 절차를 수행한다.

⑭ 플래툰 목적지 이전의 EXIT 시작 체크포인트에 도달하면
   PLATOON_EXIT 상태로 전환한다.

⑮ 리더는 완만하게 가속하고 팔로워는 완만하게 감속하여
   차량 간격을 확대한다.

⑯ 해제거리가 일정 시간 유지되면 플래툰 ID와 역할을 해제한다.

⑰ 전용 고속 통신을 종료하고 일반 V2X 및 단독 자율주행으로 복귀한다.
```

## 24. 현재 부족한 설계 항목

### 24.1 JOIN 파라미터

- 차선 변경을 먼저 할지 간격 확보를 먼저 할지 결정하는 조건
- JOIN 최대 접근속도
- 리더 최대 감속도와 팔로워 최대 가속도
- 목표거리 근접 판단범위
- 차선 중앙 오프셋 허용범위
- JOIN 안정화 시간

### 24.2 거리정보 융합

- UWB와 초음파 센서의 전환거리
- 두 센서 값이 다를 때 사용할 값
- 거리 필터링 방식
- V2X 상대속도와 거리 측정의 결합 방법

### 24.3 주행 알고리즘 인터페이스

- `LANE_CHANGE_REQUEST` 등 명령 패킷 정의
- 차선 변경 승인·진행·완료 응답 정의
- 목표속도 및 목표거리 명령 주기
- 주행 알고리즘이 명령을 거절할 수 있는 조건
- 실제 속도와 목표속도 안정 상태 응답

### 24.4 MAINTAIN 제어 파라미터

- 거리 이득 \(K_d\)와 속도 이득 \(K_v\)
- 목표 차간거리와 속도별 변화 규칙
- 플래툰 제어 계산 주기
- 목표속도 변화량 제한
- 리더 제동정보의 우선 처리 방식

### 24.5 목적지와 경로

- 플래툰 목적지 체크포인트 선정 규칙
- EXIT 시작 체크포인트 또는 거리
- 체크포인트를 놓쳤을 때 처리 방식
- 플래툰 중 경로가 변경될 때 목적지 재계산 방식

### 24.6 다중 차량 확장

- 신규 차량을 맨 뒤에 합류시키는 세부 절차
- 플래툰 내 순번과 앞·뒤 차량 ID 관리
- 차량 추가·해제 시 구성 버전 동기화
- 다중 차량의 순차적 EXIT 방식
- 리더가 모든 차량에 전송할 데이터 범위

### 24.7 ESP32 통신 설계

- 일반 V2X와 전용 통신의 정확한 전송 주기
- 브로드캐스트와 유니캐스트 스케줄링
- 메시지 우선순위
- 플래툰 전용 패킷 구조
- 통신 모드 변경 명령과 완료 응답

### 24.8 이후 추가할 예외상황

- JOIN 중 차선 변경 실패
- JOIN 중 차간거리 과도 감소
- 결합 요청·승인·설정 타임아웃
- 플래툰 전용 통신 두절
- UWB와 초음파 거리 불일치
- 리더 급정지 또는 장애물 발생
- 목적 체크포인트 누락
- 여러 차량의 동시 합류 요청
- EXIT 중 분리거리 확보 실패
- 리더 이탈 및 리더 재선정

## 25. 다음 설계 권장 순서

현재 가장 부족한 부분은 상태 이름이 아니라 각 상태 내부의 **정확한 명령, 응답 및 완료 조건**이다. 다음 순서로 구체화한다.

1. `PLATOON_JOIN` 내부 상태별 입력·출력·완료 조건 확정
2. 플래툰 알고리즘과 주행 알고리즘 사이의 명령·응답 패킷 정의
3. UWB와 초음파 거리 사용 및 전환 방식 결정
4. `PLATOON_MAINTAIN` 목표속도 계산식과 제어 주기 확정
5. 플래툰 목적지와 `PLATOON_EXIT` 시작점 결정
6. 신규 차량의 맨 뒤 합류 절차 설계
7. 다중 차량 통신과 플래툰 구성 관리 설계
8. 통신·센서·주행 제어 예외 및 타임아웃 추가

다음 작업에서는 우선 `PLATOON_JOIN`을 대상으로 각 내부 상태의 입력 데이터, 주행 명령, V2X 메시지, 완료 조건 및 실패 조건을 하나의 상태 전이표로 만드는 것이 적절하다.
